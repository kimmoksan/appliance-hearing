## 카탈로그 선택 연결 (2026-10-30)

- 청문회 PR #6은 develop에 머지됐다. 그 상태에서 별도 worktree의 feature/catalog를 만들었다. 원래 feature/hearing과 검수 카탈로그는 보존했다.
- GET /api/catalog의 전체/제품군별 조회, 선택 모델→Product 변환, 모델 없음·제품군 불일치 422, 파일 누락·깨진 JSON의 빈 목록 복구를 구현했다.
- 기본 입력은 제품군→브랜드→모델 선택이다. 목록 밖 제품은 기존 직접 입력으로 전환하고, 구매 이유는 두 경로 모두 필수다. 단종 옵션·태그를 지원한다.
- 공식 사양 원문 키·값과 출처/확인일을 보존한다. 미확인 값은 제조사 확인으로 승격하지 않는다. 구매 이유 수정과 추가 텍스트는 공식 사양을 덮어쓰지 않는다.
- `./scripts/check.ps1`: lint·타입·빌드 통과, 백엔드 **43 passed / 기존 경고 1개**. uv 캐시·pytest 임시 경로는 작업 공간 안으로 지정했다. 처음의 pytest 임시 경로 권한 오류는 경로 지정 후 해소했다.
- 실행 중인 API로 검수 카탈로그 24개와 제품군별 6개 조회, 24개 모델의 사양/확인일 일치, 미확인 2개 유지를 확인했다. 자동 테스트는 실제 카탈로그와 독립된 fixture를 쓴다.
- 브라우저 확인: 삼성 모델 선택→사양·공식 확인일, 구매 이유 빈칸 거절, 이유 수정 후 모델 유지, 제품군 변경 시 브랜드/모델 초기화, LG RG20WN의 미확인 유지, 기존 직접 입력 경로. 375px에서 인트로·제품 확인 가로 넘침 없음, 모바일 사양 표 재배치, 콘솔 오류 없음.
- `docs/catalog/`의 검수 파일은 동일 바이트 사본으로 로컬 실행에만 사용하며 수정·기능 커밋에서 제외한다. 배포/새 체크아웃에 검수 파일을 별도로 제공하지 않으면 빈 목록이 정상 동작이다.
- 미확인: 단종 옵션의 실제 브라우저 선택(현재 실데이터는 전부 판매중), 전체 브라우저·접근성, 실제 AI 연동. 단종 API/안내와 누락 파일 복구는 fixture 테스트로 확인했다. PR·CI는 이 기록 작성 후 진행한다.
