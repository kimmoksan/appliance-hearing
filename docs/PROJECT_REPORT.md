## 구현한 기능

- **제품 입력**: 제품군 → 브랜드 → 모델을 고르면 제조사 공식 스펙(확인일 표시)이 붙는다. 목록에 없으면 링크나 상품 정보를 직접 넣는다. 링크 읽기는 공개 주소만 허용하고, 리다이렉트마다 다시 검사하며, 로그인 페이지를 거부한다.
- **도트 상황 장면 12개**: 제품군마다 3개. 고정 배경 + 소품 + 상태 효과로 구성하고, 장면마다 가정과 확인 필요 조건을 카드로 보여 준다. 움직임 멈추기와 건너뛰기를 지원한다.
- **찬반 청문회**
  - 살깡이(찬성·민트), 말깡이(반대·피치), 판깡이(진행·라벤더)가 나온다. 발언 상태에 따라 동작 그림 18종이 바뀐다.
  - 모든 발언은 근거를 인용한다. 반문은 앞선 발언을 참조한다. 판깡이의 질문에 답하면 주장이 수정되거나 철회되고, 그 이유가 표시된다.
- **AI 연동**
  - 실제 모드에서 Gemini가 공방을 만든다. 출력은 서버에서 스키마와 의미 규칙으로 검증한다. 검증 항목은 근거 ID 실재, 제품 사실의 출처, 반문 대상, 수정 이유, 찬반 편이 바뀌지 않는지다.
  - 검증에 실패하면 한 번 다시 받는다. 그래도 실패하거나 한도를 넘기면 예시 공방과 이유 안내로 대체한다.
  - 판결·승자·점수 필드는 스키마에 없어서 버려진다.
- **결과와 결정**: 공방을 이득·불편·확인 필요로 정리한다. 사용자가 직접 결정과 이유를 적고 요약을 복사한다. 서버에는 저장하지 않는다.
- **예시 모드**: 키가 없어도 12개 장면 전부 장면별 대본으로 끝까지 돌아간다. 화면에 '예시 공방 · 실제 AI 응답 아님'이 항상 표시된다.

## 설계 원칙 (구현으로 강제)

- AI는 구매 판결이나 찬반 승자를 정하지 않는다. 결정은 사용자가 고른다.
- 근거는 제품 사실 / 사용자 진술 / 가정 / 확인 필요로 구분한다.
  - 제품 사실은 실제 출처가 있을 때만 쓴다.
  - AI가 웹에서 찾은 자료는 제품 사실로 인용할 수 없다.
- 단점을 감수한다는 답은 제품의 사실을 바꾸지 않는다.
- 제품 페이지와 사용자 입력은 신뢰하지 않는 데이터로 취급한다. AI에게 데이터 블록으로 전달하고, 그 안의 지시문은 따르지 않게 한다.
- API 키는 서버 환경변수에만 둔다. 키는 오류 메시지와 로그에 남지 않게 한다.
- 하루 호출 상한을 두고, 429 응답을 받으면 그날은 더 호출하지 않는다.
